# 客户端对接说明：观众 + 2 座位主动抢座

> 适用版本：协议 v1.0.0（房间模型改造后）
> 权威定义：`pkg/protocol/messages.go`、`pkg/protocol/errors.go`、`docs/PROTOCOL.md`
> 本文只写「这次房间模型改造」需要 Unity 客户端配合的点，其它协议不变。

## 1. 核心变化（一句话）

进房（`JOIN_ROOM`）默认是**观众**，不再占对战座位；只有发 `JOIN_GAME` 抢到 2 个座位之一的人才能对局。观众可以完整观战（收所有广播），但不能出杆/准备/摆位/认输。一局结束后两人**留桌**，回到「准备 → 开始」打下一局。

## 2. 新增消息

### 客户端 → 服务端

| type | 载荷 | 说明 |
|---|---|---|
| `JOIN_GAME` | （信封） | 观众抢座。成功回 `JOIN_GAME_ACK`，失败回 `ERROR` |
| `STAND_UP` | （信封） | 离座让位，回到观众席。成功回 `STAND_UP_ACK`；对局中离座=认负 |

### 服务端 → 客户端

| type | 关键字段 | 说明 |
|---|---|---|
| `JOIN_GAME_ACK` | `status:"seated"`, `seat:1|2`, `gameState` | 抢座成功（私密） |
| `STAND_UP_ACK` | `status:"stood_down"`, `gameState` | 离座成功（私密） |

## 3. 字段变更（向后兼容，客户端需读取新字段）

| 消息 | 字段 | 说明 |
|---|---|---|
| `WELCOME` | `playerNickname` / `playerAvatar?` | 新增，服务端回显当前昵称/头像 |
| `ROOM_JOINED` | `role` | 新增：`"seated"` / `"spectator"`；观众 `yourSeat=0` |
| `ROOM_CREATED` | `role` | 新增：房主也默认观众 `"spectator"` |
| `ROOM_STATE` | `spectators[]` | 新增：观众列表 |
| `GameStateDTO`（快照内） | `spectators[]` | 新增：观众列表 |
| `PlayerInfo` | `role` / `avatar?` | 新增：`role="seated"|"spectator"`；`avatar` 可选 |

> `PlayerInfo.position`：上桌玩家为 1/2，观众为 0。客户端请以 `role` 为准判断，不要只依赖 position。

## 4. 客户端需实现/需确认的接口点

1. **进房 UI 状态机**：`JOIN_ROOM` 成功后根据 `ROOM_JOINED.role` 进入「观众态」或「上桌态」。
   - `role == "spectator"`：显示「抢座/上桌」按钮，隐藏出杆/准备/认输/摆位控件。
   - `role == "seated"`：显示「离座让位」按钮，座位号用 `yourSeat`。
2. **抢座按钮** → 发送 `JOIN_GAME`；收到 `JOIN_GAME_ACK` 即上桌，收到 `ERROR(ROOM_FULL/NOT_SEATED/ALREADY_SEATED/INVALID_PHASE)` 时按 `errorCode` 提示。
3. **离座按钮** → 发送 `STAND_UP`；收到 `STAND_UP_ACK` 回到观众态。
4. **观众观战渲染**：观众与上桌玩家一样，应用以下广播并保持画面同步——
   `ROOM_STATE`、`GAME_START`、`SHOT_BROADCAST`、`STATE_UPDATE`、`BALLS_STOPPED`、`TURN_CHANGE`、`GAME_OVER`、`CUE_BALL_PLACEMENT_ACK`。
5. **观众只读约束**：观众发送 `SHOOT` / `READY` / `CUE_BALL_PLACEMENT` / `CONCEDE` / `SHOT_RESULT` / `STATE_FRAME` 会被服务端拒绝并回 `ERROR(NOT_SEATED)`。客户端 UI 层应直接禁用这些入口，避免误触。
6. **局后留桌**：收到 `GAME_OVER` 后，服务端紧接着会再推一条 `ROOM_STATE`（`roomStatus` 回到 `READY` 或 `WAITING`）。客户端**不要**在 `GAME_OVER` 后弹「退出房间」强流程，应切回「准备/开始」界面等下一局。
7. **头像/昵称**：连接参数新增可选 `avatar`（`GET /ws?playerId=&name=&avatar=&token=`），`HELLO` 也可带 `avatar`；`WELCOME` 会回显 `playerNickname` / `playerAvatar`。

## 5. 典型时序（好友房）

```
A: CREATE_ROOM                      → ROOM_CREATED(role=spectator, seat=0) + ROOM_JOINED（房主也默认观众）
A: JOIN_GAME                        → JOIN_GAME_ACK(seat=1) → 全员 ROOM_STATE
B: JOIN_ROOM{roomId}                → ROOM_JOINED(role=spectator, seat=0)
B: JOIN_GAME                        → JOIN_GAME_ACK(seat=2) → 全员 ROOM_STATE
C: JOIN_ROOM{roomId}                → ROOM_JOINED(role=spectator)（可中途进房观战）
A,B: READY{true}                    → 全员 GAME_START → 观众收全部广播
终局                                → 全员 GAME_OVER → ROOM_STATE(回 READY, 两人留桌)
B: STAND_UP                         → STAND_UP_ACK → 回观众席，座位空出
```

## 6. 错误码（新增）

| errorCode | 含义 | 触发场景 |
|---|---|---|
| `NOT_SEATED` (2009) | 当前是观众 | 观众发 SHOOT/READY/摆位/认输等上桌专属操作 |
| `ALREADY_SEATED` (2010) | 已在上桌 | 已上桌玩家再发 JOIN_GAME |

## 7. 兼容性与注意点

- 快速匹配 `QUICK_MATCH` 行为不变：配对双方自动上座（不经过观众态）。
- 房主（`CREATE_ROOM`）**也默认是观众**，需自己发 `JOIN_GAME` 抢座（统一进房都观众）。
- **固定房间号 `1000`**：客户端可直接 `JOIN_ROOM {roomId:"1000"}` 进房；该房间不存在时服务端自动懒创建，所有人写死 `roomId:"1000"` 都会进同一个房间。房间空了会按 TTL 关闭，下次再 JOIN `1000` 会重新懒创建（固定的是房间号，不是房间实例）。
- `MATCH_FOUND` / `ROOM_JOINED` 顺序仍按 roomId 归并，不依赖先后。
- 断线重连（token）对「上桌玩家」语义不变；观众断线即退出房间，重新 `JOIN_ROOM` 即可再观战。
